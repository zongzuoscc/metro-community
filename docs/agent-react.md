# 社区 ReAct 执行说明

## 实际架构

主对话先走 Spring AI Alibaba Graph 的上下文压缩/记忆流程，再进入 ReAct 检索。
ReAct 使用项目自己的结构化动作适配器与循环，不是直接实例化 Alibaba 的 ReactAgent。
这样可以继续使用冻结的 PreparedUserAiChat，保留平台/BYOK 路由、安全网关与调用治理。

执行顺序：

1. 先查站内文章；用户开启联网时，即使站内有资料也执行一次联网查询。
2. 模型接收原始问题、近期对话/内部摘要、工具实际返回的证据与状态。
3. 返回 CALL（白名单工具＋查询文字）或 FINISH；不要求输出、不记录内部思维链。
4. 后端检查权限、参数、重复调用、运行权和预算，执行后把真实 observation 交给下一步。
5. 模型选择 FINISH，或资源/无进展边界触发后，结合已取得的资料生成最终答案。
6. 答案继续经过引用校验与原有持久化完成事务，再通知前端。

不同查询可以重复调用同一工具。相同工具和规范化参数不会重复访问下游；
连续两次没有新增证据会停止，防止重复搜索空转。观察包含实际资料而非只有命中数量。
文章按稳定来源标识累积，网页按 URL 去重，并统一重编号，避免多次联网的 W1 指向不同网页。

## 边界与成本

- 只能查询文章、当前用户记忆、当前主对话历史、联网资料；模型没有写工具、用户身份参数、SQL 或 HTTP 执行接口。
- 临时对话不读取/写入持久记忆和历史；关闭记忆不能被模型绕过；关闭联网不能被模型绕过。
- 联网初次请求使用当前用户问题。后续联网动作必须经过独立的公共查询生成节点：它只接收当前问题与公开文章/网页，不接收私有历史、记忆或主决策提出的查询；公开观察中的内部查询也替换为当前问题。主决策不能直接把私有资料生成的查询发给搜索服务。用户当前问题仍会发送给联网服务，这不是自动识别所有敏感信息的 DLP 系统。
- 最大决策步数默认 6、工具尝试默认 8（包含初始检索）；兼容旧环境变量 METRO_AI_PLANNER_MAX_ROUNDS/MAX_TOOL_CALLS，部署硬上限为 16/24。
- 6 步指主循环决策次数，并非整轮模型调用总数；公共查询生成、HyDE、必要的上下文压缩与最终回答会额外调用模型，也受各自配额与整轮截止时间限制。
- 老 .env 若显式保留 2/4 会继续生效，应按需要改为 6/8。默认单次决策 PT6S，整轮还受总 deadline 和最终生成时间预留约束。
- Agent 的短窗口限额按模型调用计数，包含 ReAct 与 HyDE，不是用户问题数。默认由每分钟 8 调整至 24，避免一个合法多步请求自行耗尽旧限额；每天 100 次不变。达到配额会明确失败，不绕过计费保护。
- 决策输出最多 512 token；输入按真实序列化提示词估算预算。必需的问题和最新观察放不下时明确失败，不假装理解完整资料。
- 每个动作边界检查运行租约；取消后不再发起后续动作。已经发往供应商的请求可能仍执行/计费，不能承诺撤销。
- 记忆修改代际在压缩完成后冻结；后续模型请求发送前与返回后重新检查。期间删除或修改记忆会终止使用旧资料的回答，不把运行中已缓存的旧记忆继续交给下一次模型调用。
- 文章/历史/联网故障会作为 ERROR 观察，模型可以选择别的来源。记忆 Embedding/Milvus 故障与前次改造约定一致：明确失败，不退回词法记忆。
- 决策格式错误或决策模型失败也明确失败，不悄悄变回固定计划。

## 验证与部署

单元测试覆盖动作解析、实际观察、动态查询、重复工具、取消/权限、引用合并与输入预算，
以及嵌套 HyDE/Embedding 的冻结路由和实际发送前检查。2026-09-09 本地完整验证：
68 个测试类、370 项测试通过，三个角色 Jar 构建成功；集成测试和真实模型联调未运行。
JDK 21 下执行：

```sh
./mvnw -q clean -Dtest='*Test,!*IntegrationTest,!*IT,!RecommendationMetricsTaskTest' test package
```

ReAct 本身不新增数据库表；一起交付的记忆改造仍需要先执行 [记忆升级步骤](agent-memory-compaction.md)。
构建/Mock 测试不代表真实模型任务成功率或高并发容量，部署后需用真实模型校准步数、延迟和成本。
