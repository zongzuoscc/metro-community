# Spring AI Alibaba 与回答前记忆压缩

用户已确认直接实施。范围只涉及社区后端；不改运维项目、不改前端历史展示，不把旧聊天记录替换或删除。

## 执行顺序

1. 接入兼容现有 Spring AI 的 Alibaba Graph，在回答前执行上下文准备；继续复用带预算、超时、BYOK 与 SSRF 防护的模型网关。
2. 按模型输入 token 预算检查尚未压缩的完整轮次。超阈值时用模型一次生成内部摘要和结构化记忆，保留最近完整轮次；当前问题不参与历史压缩。主对话 checkpoint 与用户/上下文边界绑定。
3. MySQL 保存记忆事实与待投影记录；Milvus 按记忆版本 ID 幂等写入。仅在向量可见后启用新的压缩 checkpoint；失败不删原文、不偷偷改用词法匹配。
4. 长期记忆检索改为持久向量召回，再回 MySQL 校验归属、状态、版本、有效期。关闭记忆时不提取/检索记忆；临时对话完全绕开持久路径。保留文章 BM25 和旧历史检索。
5. 删除回答后的规则捕获入口；测试阈值、顺序、失败重试、用户隔离、修改/删除、近期原文保留与现有回归。运行三个角色构建，真实服务验证单独说明。

## 关键约束

- 模型、Embedding、Milvus 调用不能持有 MySQL 事务或行锁。
- 摘要只压缩成功的完整轮次，不能把模型编造的内容作为用户事实；输出必须带用户消息来源并经过安全校验。
- 摘要、记忆记录采用持久幂等键；并发/reset/关闭记忆后旧任务不能覆盖新边界。
- 只读 Planner 仍最多两轮、四工具；Graph 不自动扩大权限。
- 测试先于实现，中文注释解释事务、幂等和失败边界；保留既有未提交文档。
