# 前端纸感技术社区改造设计

## 目标与范围

本轮优先完成桌面端的前端视觉统一，重点重做文章发布和编辑页。产品仍是面向技术内容创作与讨论的社区，不复制知乎的蓝白信息流外观，而是以有作者感的纸感编辑体验形成差异。

改造范围包括首页、文章详情、发布页、认证页、个人中心、收藏、消息、聊天和管理后台。移动端本轮只保证页面可访问、布局不溢出，不实现完整的手机写作流程。个性化推荐、AI 能力和新的后端接口不属于本轮。

## 参考与取舍

- iA Writer：以专注写作和低干扰状态反馈为参考，编辑状态不应打断输入。
- Substack：以文章排版和作者感为参考，标题与正文具有明确的阅读层级。
- Notion：以自动保存与工具状态的静默呈现为参考，状态信息可见但不抢占注意力。

不采用深色高密度工作台，也不采用知乎式的蓝色卡片堆叠。产品采用暖白底色、细分隔线与有限强调色，不依赖在线字体或装饰图片。

## 视觉系统

- 背景：暖白与浅砂色分层，正文阅读面保持接近纸张的纯净度。
- 字体：标题优先使用系统宋体族，正文使用系统无衬线字体，保证不同设备的中文可读性。
- 强调色：低饱和砖红用于发布、选中、关键数字和风险动作。蓝色不再作为默认主色。
- 表面：以细边框、轻微明暗差和留白区分区域，避免泛滥阴影和无意义卡片。
- 圆角与间距：使用小圆角和统一间距标尺，编辑、阅读和管理页面共享按钮、标签、输入框与提示状态。

## 页面设计

### 发布和编辑页

桌面端采用双栏结构：左栏承载封面、标签、字数、阅读时长与草稿状态，右栏为标题和 Markdown 编辑器。顶部为返回、文稿状态和模式说明，底部固定草稿与发布操作。

标题采用宋体风格的大字号排版，正文编辑区保持高对比和大行距。工具栏保持紧凑，避免把每个功能做成明显按钮。上传封面和标签不再独占大面积区域，未配置时显示低干扰的空状态。

输入停止约 1.5 秒后触发一次草稿保存。状态按“正在保存”“已保存”“保存失败”切换，固定占用同一位置，避免按钮和文本跳动。自动保存不会离开当前页面，手动保存草稿后仍停留编辑页，只有显式发布成功后才跳转。

### 阅读和社区页面

首页、文章详情与个人中心使用统一的内容栏宽度和纸感阅读面。首页的信息流加强标题、作者、标签和摘要的层级，减少大块白卡。文章详情突出标题、元信息和正文，互动操作收纳为紧凑工具条。

认证页保留简洁表单，但使用统一的暖白背景、砖红主操作和更清晰的输入焦点。消息、聊天、收藏和个人设置沿用同一套表面与状态样式。管理后台维持高效表格与筛选布局，只共享颜色、字体、间距和反馈组件，不强行套用文章阅读排版。

## 交互与可访问性

- 键盘写作是发布页的首要场景，Tab 顺序、输入焦点和快捷操作需清晰可见。
- 主操作和草稿操作使用一致尺寸，状态切换不改变工具栏高度。
- 颜色不作为唯一状态表达，保存状态同时提供文字和图标或边框变化。
- 关键文字与背景满足可读对比，长中文标题、标签和按钮文本不得溢出。
- 窄屏下发布页折叠为单栏，信息栏移至编辑器上方，底部操作始终可达。

## 实施边界

前端继续使用 Vue 3、Vite、Element Plus 和现有 Markdown 编辑器，不增加在线字体、UI 模板或 mock 数据。保留当前 API 形状和现有 `token` 上传头，后续可与后端 Bearer Token 迁移兼容。

实现会先建立全局设计变量和共享组件样式，再逐页迁移。发布页的自动保存会复用现有草稿接口，但避免手动草稿保存的跳转行为影响自动保存。

## 验证

- 运行前端构建，确保所有页面可编译。
- 以真实后端接口或已有数据验证发布、草稿、封面上传、标签和编辑回填。
- 在桌面宽度和 375px 窄屏分别检查发布页、首页和文章详情，确认没有横向溢出、固定操作遮挡或中文文本截断。
- 截图检查首屏是否具备明确的纸感、标题层级和品牌识别，避免重新退化为通用卡片界面。
