# Metro Agent 混合回答与主对话时间轴设计

## 目标

把 Agent 从“没有站内证据就拒答”调整为正常的混合回答，并让用户看清每段内容来自模型知识、站内文章、个人记忆、主对话历史还是联网资料。保持每个用户只有一条长期主对话；临时对话仍不持久化。

## 回答与联网

- 每轮先召回有权限的站内文章、长期记忆和主对话历史，再组织模型知识。
- 主对话默认联网，即使站内已有资料也联网补充和核实；用户可以关闭。
- 联网开关保存在主对话服务端记录中，跨刷新、登录和设备保持。
- 临时对话创建时继承主对话开关，只在临时会话内修改，退出后不反向更新主对话。
- 联网失败不阻断回答，界面明确显示“本次联网检索失败”。搜索查询不得携带记忆原文、私密历史或用户身份信息。
- 回答正文使用简短来源标记，底部提供可展开来源卡片。站内文章与网络页面提供可点击链接；模型知识明确提示可能过时；记忆和历史只显示用户可识别的摘要，不泄漏完整私密上下文。
- 对来源冲突明确并列差异；高时效事实优先采用较新的权威网络来源。

## 全屏主对话时间轴

- 小窗不显示历史导航；只有全屏模式显示左侧窄时间轴。
- 每轮完整问答对应一个刻度，不创建多个独立会话，也不使用日期分组列表。
- 悬停刻度显示问题开头、回答前两至三行和时间；点击后在同一主对话内平滑定位。
- 主对话滚动时同步高亮当前刻度；长时间线支持分页加载、压缩刻度和历史搜索命中高亮。
- 临时对话不生成刻度、不进入搜索，退出或到期后删除。

## API 设置与本轮边界

- 用户 API 配置只放在“我的设置 → AI 模型”，不占用桌宠小窗。
- 预设供应商填写供应商、模型和 API Key；自定义兼容接口额外填写公网 HTTPS 地址。
- API Key 继续由后端 AES-256-GCM 加密后存入数据库，前端不保存、不回显明文，仅显示末四位提示。
- 本轮不实现用户 Skill，也不实现图片、文件和语音输入。

## 验收

- 无站内资料时仍可返回带“模型知识”标记的回答。
- 有站内资料时仍执行联网，并分别展示站内与网络来源；关闭联网后不发出搜索请求。
- 主对话联网偏好跨设备保持，临时会话修改不污染主对话。
- 全屏可悬停、点击并定位任意已加载问答；小窗和临时模式不显示时间轴。
- 来源链接、隐私边界、跨账号状态清理、迟到响应隔离和 API Key 不回显均有自动化测试。
